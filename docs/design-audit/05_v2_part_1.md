# FAN:GO 디자인 v2 컨셉 분석 (1부) — signup_view_concept_v2.html

- 원본: 사용자가 채팅에 직접 첨부한 `signup_view_concept_v2.html` (회원가입 "계정 생성" 화면 컨셉, 단일 HTML 파일)
- 확인 방법: **HTML 텍스트만 파싱한 게 아니라, 실제로 브라우저(headless Microsoft Edge)에 로드해서 렌더링한 스크린샷을 직접 눈으로 확인함.** 파일은 전부 인라인 스타일이라 외부 CSS 캐스케이드나 JS 동작이 없어, 렌더링 결과가 스타일 속성값과 1:1로 정확히 대응됨(즉 계산값 기준의 판독 신뢰도가 높음).
- 이번 분석 범위(6개 구간만): **1. 최종 수정안 / 2. 개요 & 원칙 / 3. 컬러 / 4. 타이포그래피 / 5. 여백 & 그리드 / 6. 라운드 & 그림자**
- 비교 기준: v1 가이드 분석 4파일(`00_project_structure.md`, `01~04`)에 정리된 값들 + 실제 코드베이스(`src/SignupView.jsx`/`.module.css`, `src/index.css` 토큰)
- 코드 수정 없음 — 이 문서는 내용 기록·비교 전용
- 상태 표기 기준: **v1 유지**(v1 규정값과 동일) / **v1 값 변경**(같은 범주지만 수치·색상이 다름) / **v1 대체**(v1이 규정한 패턴 자체를 다른 방식으로 교체) / **v2 신규**(v1에 대응 규정이 아예 없던 새 요소)

## 렌더링 확인 (스크린샷)

400×900 뷰포트로 headless 브라우저 렌더링 결과, 280px 고정폭 카드(모서리 32px 라운드, 옅은 테두리)가 중앙에 배치됨. 위에서부터: 흰 헤더 바(뒤로가기 버튼만) → "계정 생성" 타이틀 → 이메일(+중복확인 버튼) → 비밀번호 → 비밀번호 확인 → 닉네임 → 국적(드롭다운) → 휴대전화번호(+82 국가코드) → 약관 체크박스 3개 → "다음 →" 보라 필(pill) 버튼.

**⚠️ 렌더링 중 실제로 발견된 레이아웃 버그**: 이메일 입력 필드 옆 **"중복확인" 버튼이 카드 폭을 벗어나 카드의 `overflow:hidden` 경계에서 텍스트가 잘림**(스크린샷에서 "중복확인" 버튼 우측이 카드 밖으로 밀려 잘려 보임). 원인: 이메일 `input`에 `flex:1`만 있고 `min-width:0`이 없어서, placeholder 텍스트("mina_tan@example.com")의 내재 폭(intrinsic width) 때문에 입력창이 충분히 줄어들지 못하고, 그 옆의 "중복확인" 버튼(`white-space:nowrap`, 고정 패딩)을 카드 밖으로 밀어냄. 이건 텍스트만 읽어서는 알 수 없고 **실제 렌더링을 해야만 발견되는 문제**였음.

### 가장 중요한 발견 3가지

1. **헤더 구조 자체가 v1과 다른 방향** (V2-002, 003, 023) — v1은 "헤더는 항상 Primary 전면 채움 + 중앙 로고 + squircle 버튼"을 원칙으로 못박았는데, 이 v2 컨셉은 **흰 배경 헤더 + 로고 없음 + 다른 모양의 버튼**으로 완전히 다른 패턴을 보여줌. 새 화면 디자인 방향이 바뀐 것인지, 이 화면만의 예외인지 확인 필요.
2. **버튼 형태의 이원화** (V2-006, 041 vs V2-042) — 같은 화면 안에서 "중복확인"은 v1 규정대로 12px squircle인데, CTA "다음 →"는 100px 완전 pill — v1의 "일관성" 원칙(V2-012)과 정면으로 부딪힘.
3. **Primary-500(#6D57FC) 실측 근거 확보** (V2-016) — v1 PDF 자체에서는 안 보이던 Primary Scale 컬러의 실제 hex를, 이번 v2 파일이 코드 토큰과 정확히 같은 값으로 다시 한번 확인시켜줌 — 이 부분만큼은 긍정적 재확인.

또한 CTA 버튼의 "다음 →" 라벨(V2-015)은 v1 스스로도 내부 문서 간 충돌이 있던 "화살표 금지" 규칙에 또 한 번 걸리는 사례로, 마스터 문서(`04_v1_master.md`)의 6-1 충돌 항목과 함께 다뤄야 할 이슈로 남겨둠.
