# FAN:GO 디자인 가이드 v1 + v2 통합 마스터

- 대상: v1 PDF 전체 분석(`04_v1_master.md`) + v2 HTML 전체 분석(`05~08_v2_part_1~4.md`)를 대조 후 하나로 통합
- v2 원본: `signup_view_concept_v2.html` (사용자가 대화에 직접 첨부, 파일시스템에도 `C:\Users\asia\Downloads\signup_view_concept_v2.html`로 존재 확인)
- 코드 수정 없음 — 통합·검수 전용 문서. 기존 파일(`04`~`08`) 전부 열람만 하고 수정·삭제하지 않음
- 적용 기준(사용자 지시 원문 그대로):
  1. v1을 기본 디자인 기준으로 유지
  2. v2와 충돌하면 v2 우선
  3. v2에서 변경하지 않은 v1 규칙은 유지
  4. 판독하지 못한 부분은 추측 금지

## 0. ⚠️ 최우선 보고 — 개수 대조 결과 (요청하신 PNG~20 / SVG~44 / 표~41과 실측이 다름)

사용자가 제시한 참고 개수와, 제가 실제로 가진 v2 원본(`signup_view_concept_v2.html`)을 직접 재검수한 개수가 **다릅니다**. 추측으로 맞추지 않고 실측 결과를 그대로 보고합니다.

| 항목 | 사용자 제시 개수 | 실측 확인 개수 | 확인 방법 |
|---|---|---|---|
| PNG 이미지 | 약 20개 | **0개** | HTML 원문에서 `<img` 태그 검색 → 일치 0건 |
| SVG | 약 44개 | **0개** | HTML 원문에서 `<svg` 태그 검색 → 일치 0건 |
| 표(table) | 약 41개 | **0개** | HTML 원문에서 `<table` 태그 검색 → 일치 0건(이 파일은 폼 레이아웃만 있고 표 형태의 데이터가 없음) |

**재확인한 사실**:
- 제가 이번 v2 분석(1~4부, `05`~`08`)에서 다룬 v2 자료는 **`signup_view_concept_v2.html` 단일 파일 하나**뿐입니다. 사용자가 대화에 이 파일을 두 차례(이번 요청 이전에 한 번, 그리고 최초 1부 분석 때 한 번) 첨부하셨는데, **두 번 모두 내용이 완전히 동일**했습니다.
- 파일시스템 전체(Downloads, Desktop, 프로젝트 폴더)를 다시 검색해도 이 파일 외에 다른 `*v2*.html`이나 v2 관련 이미지·PDF 자산은 **발견되지 않았습니다**(검색 결과: `signup_view_concept_v2.html` 1건만 v2 관련 HTML로 존재, 나머지는 무관한 문서 파일들).
- 이 HTML은 전체 86줄, `<div>` 23개, `<h1>~<h6>` 0개(타이틀도 스타일 입힌 `<div>`), 인라인 스타일만 있고 외부 CSS·JS·이미지 리소스를 전혀 불러오지 않는 **순수 마크업+인라인 스타일 조각**입니다.

**결론**: 요청하신 PNG~20/SVG~44/표~41개라는 규모는, 제가 지금 갖고 있는 이 단일 HTML 스니펫보다 **훨씬 큰 문서**(아마 v1 PDF처럼 여러 페이지·여러 화면을 담은 정식 v2 디자인 가이드나, 여러 화면의 PNG 목업 모음)를 가리키는 것으로 보입니다. **판독하지 못한 부분을 추측하지 않는다는 원칙에 따라, 존재하지 않는 PNG/SVG/표를 있다고 지어내지 않았습니다.** 만약 별도로 전달하려 했던 v2 전체 자료(더 큰 PDF, 여러 화면 HTML, 이미지 파일 모음 등)가 있다면 다시 전달해주셔야 이번 통합에 반영할 수 있습니다. 이번 문서는 **제가 실제로 받은 범위(회원가입 화면 1개, 이미 V2-001~100으로 전부 분석 완료)**를 기준으로 통합했습니다.

## 1. 대조 방법

1. `04_v1_master.md`(v1 전체, 1~43페이지 통합본)를 처음부터 끝까지 재확인.
2. `05`~`08`(v2 1~4부, V2-001~100)를 처음부터 끝까지 재확인.
3. v2 원본 HTML을 다시 열어 제목(타이틀 텍스트)·표·이미지·SVG·Before/After 유무를 태그 단위로 재검색(위 0번 항목).
4. 두 세트를 항목별로 대조하여, **v2가 실제로 값을 제시한 항목만** "충돌 시 v2 우선" 규칙을 적용해 최종값을 정함. v2가 언급하지 않은 v1 항목은 전부 유지.
5. 접근성 위반·명시적 금지 규칙과 충돌하는 경우는 기계적으로 "v2 우선"을 적용하면 오히려 기준이 후퇴하므로, **별도 절(4번 섹션)에서 예외로 강하게 표시**하고 자동 채택하지 않음(판독 불확실이 아니라 "규칙 적용의 부작용"이라 별도 처리 — 사람 확인 필요로 명시).

### 6-1. 즉시 수정 권장(접근성·명시적 금지 규칙 — v1 기준으로 되돌리거나 지켜야 함)

### 6-2. 사람 결정이 필요한 항목(v1↔v2 충돌, 전역 영향 큼)
- M-H-001/M-C-002/M-R-003/M-S-006/M-H-003: 헤더 구조를 흰 배경·1존으로 바꿀지

## 7. 결론

1. **개수 불일치가 가장 중요한 발견입니다.** 요청하신 PNG~20/SVG~44/표~41개는 제가 가진 v2 자료(회원가입 화면 HTML 1개, PNG 0/SVG 0/표 0)와 규모가 전혀 다릅니다 — 더 큰 v2 자료가 따로 있다면 다시 전달 부탁드립니다.
2. 현재 가진 범위 안에서는 **v2가 "헤더 구조", "아이콘 구현 방식", "CTA 버튼 형태", "다음 버튼 화살표"라는 4가지 큰 축에서 v1과 정면으로 다른 방향**을 보여주고 있고, 이 4가지는 전역 컴포넌트에 영향을 주기 때문에 기계적으로 "v2 우선"을 적용하지 않고 **사람 결정이 필요한 항목으로 명시적으로 남겨뒀습니다.**
3. **접근성 관련 3건**(터치 영역, 체크박스 시맨틱, 텍스트 대비)은 v2 값을 그대로 채택하면 기준이 후퇴하므로, 이번 통합에서는 **v1 기준을 유지하는 쪽으로 결론**짓고 실제 반영 시 v2의 미달 수치를 쓰지 않도록 명시했습니다.
4. 그 외 색상·간격·라운드 값들(약 20건)은 충돌 시 v2 값을 최종 채택값으로 정리했고, v2가 아예 다루지 않은 카테고리(배지·칩, 우선순위 카드, 팝업 본체, 리스트, 탭, 하단내비, 기타 컴포넌트, 스플래시/로딩/에러 등)는 `04` 문서의 v1 내용을 그대로 유지합니다.
