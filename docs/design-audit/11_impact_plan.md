# v2(v29) 변경사항 요약 — 실제 코드 반영 영향도 분석

- 참고 자료(요약본): `20260913_FANGO_변경사항요약_v1.md`(사용자 첨부, 기준 문서 `guide_v29_final.html`의 "v2 뱃지" 21건 요약)
- **최종 판단 기준은 이 요약이 아니라 `docs/design-audit/09_v1_v2_master.md`**입니다 — 이 문서는 요약본의 21건 중 실제로 코드에 반영해야 하는 항목만 골라, 프로젝트 전체를 검색해서 영향받는 파일을 정리한 것입니다.
- 코드는 **전혀 수정하지 않았습니다.** 아래 표는 영향 파일 목록이며, 사용자 확인 후 실제 반영을 진행합니다.
- 조사 방법: `grep`으로 관련 패턴을 프로젝트 전체(`src/*.jsx`, `src/*.module.css`)에서 검색하고, 필요한 곳은 실제 코드를 열어 현재 구현 상태를 직접 확인함.

### 백엔드 확인 필요
- 요약본 자체에는 백엔드 API 변경을 직접 요구하는 항목이 없습니다. 다만 다음은 **백엔드 데이터와 맞물린 프론트 로직**이라 함께 확인이 필요합니다:
  - "저장한 동선" 중복 데이터 원인(요약#5) — 화면은 삭제됐지만, 동일한 데이터 중복 현상이 "나의 일정"(`HistoryView`)에서도 나타나는지는 백엔드 응답 데이터 확인이 필요할 수 있음
  - 부분 영역 에러(요약#20)의 실제 대상(예: 이동시간 조회 API)이 얼마나 자주 실패하는지는 백엔드/카카오맵 연동 상태 확인 필요

### 운영 규칙(코드 변경 전 사람이 먼저 결정해야 함)
- **하단 버튼 3개 vs 2개(요약#4)** — 이번 세션 사용자 요청("동선보기" 복원)과 정면 충돌, 최종 방향 확정 필요

- **Primary-100/200 등 색상 hex 확정**(`10_token_mapping.md` 참고) — "다시 시도" 버튼 보더 색을 정확히 어느 값으로 할지는 토큰 확정이 선행되어야 함
